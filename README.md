# Продажа выпуска продукции между организациями (1С:ERP 2.5)

Общий модуль `АвтоПродажаВыпускаМеждуОрганизациями`:
[`src/CommonModules/АвтоПродажаВыпускаМеждуОрганизациями/Module.bsl`](src/CommonModules/АвтоПродажаВыпускаМеждуОрганизациями/Module.bsl).

## Что делает

Берёт проведённые документы **«Этап производства»** (`ЭтапПроизводства2_2`) организации-продавца
в статусе *Завершен* за день, табличную часть «Выходные изделия», где получатель — склад. На каждый
склад выпуска создаёт и проводит цепочку документов:

| Организация | Документ | Как заполняется |
|---|---|---|
| Продавец | Реализация товаров и услуг | `Заполнить()` по структуре → типовые значения по умолчанию; цены — `ЦенообразованиеСервер.ЗаполнитьЦены` по виду цены; НДС и суммы — `ОбработкаТабличнойЧастиСервер.ОбработатьТЧ` |
| Продавец | Счет-фактура выданный | `Заполнить(Реализация)`: типовой ввод на основании |
| Покупатель | Приобретение товаров и услуг | `Заполнить()` по структуре; строки, цены и суммы копируются из реализации без пересчёта; входящий номер и дата берутся из реализации |
| Покупатель | Счет-фактура полученный | `Заполнить(Приобретение)`: типовой ввод на основании; номер и дата — как у счёта-фактуры выданного |

Документы датируются концом дня (23:59:59), то есть проводятся после всех этапов этого дня.
Все четыре документа по складу создаются в одной транзакции: если хоть один не провёлся, не
создаётся ни один.

**Повторный запуск за тот же день** ничего не дублирует: ранее созданные документы находятся по
метке `#АвтоПродажаВыпуска#` в комментарии, перезаполняются и перепроводятся. Если выпуска по
складу больше нет, вся цепочка помечается на удаление. Правки, внесённые вручную в эти документы,
при повторном запуске теряются.

### Партионный учёт

Модуль не пишет движения сам: всё проводится типовым кодом документов в неоперативном режиме.

- Виды запасов в реализации и приобретении заполняет типовой код при проведении (флаг
  `ВидыЗапасовУказаныВручную` сбрасывается, поэтому при перезаполнении партии определяются заново).
- Себестоимость реализации у продавца и стоимость партии у покупателя рассчитывает типовое
  «Закрытие месяца → Расчёт себестоимости». Стоимость партии у покупателя равна сумме приобретения
  без НДС (или с НДС, если покупатель НДС не принимает к вычету) и от себестоимости продавца не зависит.

## Использование БСП

`ОбщегоНазначения.ЗначениеРеквизитаОбъекта`, `ЕстьРеквизитОбъекта`, `СообщитьПользователю`,
`ХранилищеОбщихНастроекСохранить/Загрузить`, `ПриНачалеВыполненияРегламентногоЗадания`,
`КодОсновногоЯзыка`; `ОбщегоНазначенияКлиентСервер.ДополнитьМассив`;
`ПрефиксацияОбъектовКлиентСервер.НомерНаПечать` (номер без префиксов для входящих номеров);
`ОбработкаОшибок.КраткоеПредставлениеОшибки/ПодробноеПредставлениеОшибки`; журнал регистрации.

## Установка (в расширение)

1. Добавьте в расширение общий модуль `АвтоПродажаВыпускаМеждуОрганизациями` с флагом «Сервер»
   и вставьте в него код.
2. По желанию добавьте регламентное задание `АвтоПродажаВыпускаМеждуОрганизациями` с методом
   `АвтоПродажаВыпускаМеждуОрганизациями.ВыполнитьРегламентноеЗадание` (например, ежедневно в 01:00).
   Оно формирует документы за предыдущий день по всем сохранённым наборам настроек. Если задание
   не нужно, удалите процедуру `ВыполнитьРегламентноеЗадание`: иначе расширение не пройдёт проверку
   из-за ссылки на отсутствующие метаданные.

## Пример вызова

```bsl
Настройки = АвтоПродажаВыпускаМеждуОрганизациями.НовыеНастройки();
Настройки.ОрганизацияПродавец   = Справочники.Организации.НайтиПоНаименованию("Производство");
Настройки.ПартнерПокупатель     = Справочники.Партнеры.НайтиПоНаименованию("Торговый дом");
Настройки.КонтрагентПокупатель  = Справочники.Контрагенты.НайтиПоНаименованию("Торговый дом");
Настройки.ВидЦены               = Справочники.ВидыЦен.НайтиПоНаименованию("Внутригрупповая");
Настройки.ОрганизацияПокупатель = Справочники.Организации.НайтиПоНаименованию("Торговый дом");
Настройки.ПартнерПоставщик      = Справочники.Партнеры.НайтиПоНаименованию("Производство");
Настройки.КонтрагентПоставщик   = Справочники.Контрагенты.НайтиПоНаименованию("Производство");
Настройки.СкладПоступления      = Справочники.Склады.НайтиПоНаименованию("Склад ТД");
// Необязательно: СоглашениеСКлиентом, ДоговорСКлиентом, СоглашениеСПоставщиком, ДоговорСПоставщиком, СкладОтгрузки.

// Разовый запуск
Результат = АвтоПродажаВыпускаМеждуОрганизациями.СформироватьДокументыЗаДень(ТекущаяДатаСеанса(), Настройки);
Для Каждого ТекстОшибки Из Результат.Ошибки Цикл
    Сообщить(ТекстОшибки);
КонецЦикла;

// Перезаполнение за период
АвтоПродажаВыпускаМеждуОрганизациями.СформироватьДокументыЗаПериод('20260901', '20260930', Настройки);

// Настройки для регламентного задания (можно несколько пар организаций)
НаборыНастроек = Новый Массив;
НаборыНастроек.Добавить(Настройки);
АвтоПродажаВыпускаМеждуОрганизациями.СохранитьНастройкиРегламентногоЗадания(НаборыНастроек);
```

Для покупателя и продавца заведите партнёров и контрагентов, соответствующих друг другу организаций
(ИНН/КПП контрагента = ИНН/КПП организации). Если соглашения или договоры обязательны по вашим
настройкам учёта, укажите их в настройках.

## Что сверить с вашим релизом ERP 2.5

Код не компилировался на конкретной базе. Имена типовых методов и реквизитов ниже от релиза к релизу
менялись, поэтому перед запуском проверьте синтаксис в Конфигураторе и сверьте их с глобальным
поиском по конфигурации:

| Место в модуле | Что проверить |
|---|---|
| `ВыпускЗаДень` | Реквизиты `ЭтапПроизводства2_2.ВыходныеИзделия`: `Получатель`, `Назначение`, `Серия`; значение `Перечисление.СтатусыЭтаповПроизводства2_2.Завершен` |
| `ПараметрыЗаполненияСтавкиНДС` | Как в модуле формы `РеализацияТоваровУслуг` формируется параметр действия `"ЗаполнитьСтавкуНДС"`. Скопируйте тот же вызов |
| `ЗаполнитьЦеныИСуммы` | Сигнатура `ЦенообразованиеСервер.ЗаполнитьЦены` и ключи `ПараметрыЗаполнения` (`Дата`, `Валюта`, `ВидЦены`); при новом ценообразовании 2.5 сверьте с вызовом в форме реализации |
| `ЗаполнитьСтатусыУказанияСерий` | `Документы.<Документ>.ПараметрыУказанияСерий` и `НоменклатураСервер.ЗаполнитьСтатусыУказанияСерий` |
| `СчетФактураПоОснованию` | Табличная часть `ДокументыОснования` у счетов-фактур |
| `СформироватьЦепочку` | У счёта-фактуры полученного номер и дата поставщика хранятся в `Номер`/`Дата`. Если в релизе включён контроль уникальности номера, замените на соответствующие реквизиты |

## Ограничения

- Берётся только основной выпуск на склады. Выпуск в подразделение и побочные изделия (`ПобочныеИзделия`) не учитываются.
- Прослеживаемые товары (РНПТ) и маркировка не обрабатываются.
- Цепочки разных дней и складов независимы: ошибка по одному складу не останавливает остальные.
  Ошибки возвращаются в результате, пишутся в журнал регистрации (событие «Продажа выпуска между
  организациями») и выводятся сообщением пользователю.
